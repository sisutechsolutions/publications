
REPORT: Critical Account Takeover (ATO) Vulnerability Via Recycled Phone Number and Flawed Deactivation Logic
AUTHOR: Paul Lehto
ICOD: 8/13/2025 (11:38 a.m. EST)
PUBLISHED: 11/22/2025 

SUMMARY: A critical multi-factor authentication (MFA) bypass vulnerability was discovered in the TikTok web application via Google Chrome browser. This issue allows an unauthenticated attacker to gain full control of a user's account via a recycled phone number and intercepting the required SMS authentication code for new account creation. This vulnerability could lead to a complete account takeover, allowing the attacker to post content, access private information, and interact with other users as if they were the legitimate account holder.

1. VULNERABILITY MECHANISM: The failure points to handling the transfer of a phone number from one user to another and disassociating the number from the original user's account when the number was deactivated or reissued. 

2. ROOT CAUSE ANALYSIS: Improper Database Slate Management
- The user’s account could be flagged as “active” or “unverified”, but the phone number entry was never permanently cleared from the account credentials. 
- Upon new account creation, the system found the associated phone number with the original user account. Due to the logic flaw, the system handled the successful SMS verification as a valid login for the original user account.

3. VERIFICATION: The phone number used for the test was obtained from a US carrier after recycling/re-assignment, confirming it was a recycled number that failed to be de-associated with the user account. The new account creation process includes a phone number field, to which an SMS MFA request was sent. The OTP entry was successful and granted full access to an existing user account. The failure to de-associate the recycled number from the account confirms this vulnerability. It relies on the system’s failure to securely handle the recycling of phone numbers.

7. ANALYST COMMENTS: My discovery of this vulnerability was spontaneous. My original intentions were to create a Tiktok account for marketing a new online business I had created. I used Chrome browser to begin the registration process and entered my business email and cell number. This triggered an SMS MFA request to my cell phone, and after entering the OTP I was redirected to an existing Tiktok account. Upon discovery I was able to view the user account dashboard with full access. I replicated the process to test my theory whether this was a fluke or indeed a vulnerability. With the mechanism clear, I documented the process to include POCs, being careful to censor any PII associated with the account. I then promptly logged out of the compromised account. Afterwards I created a report and submitted it to Tiktok via HackerOne. The security team at TikTok reviewed it and marked it as “Informational” and closed the ticket. I’ve published this vulnerability after a 90-day waiting period. All steps have been taken to ensure this matter was handled ethically and professionally with all parties involved.
